# 工作台开发与交付报告模板

适用于阶段交接、暂停及最终交付。复制八段并用实测结果填写；不适用写「不适用—原因」，未执行写「未验证—原因」，缺失数字不得填 0 或通过。阶段简报可保持五行，最终或停修报告用本模板。用户指定其他格式时从其要求。

## 1. 结论与资源消耗

- 病种／版本／里程碑与闸口：{状态、阻断、能否安装及使用}。
- 起止时间、时区、实际耗时：{数据来源}。
- 实际模型与角色：{主模型、各角色模型及来源；不可见写未取得；模型切换记录时间}。
- Token：{输入、输出、缓存、累计或各角色用量；说明统计范围、来源、是否估算；不可见写未取得}。剩余额度：{实际可见值及时间；不可见写未取得}。预测消耗独立标「估算」，不与实耗混写，也不重复累加包含子任务的总计。
- 使用工具：{工具/版本或通道、用途、主要结果与限制；不记录凭据、真实病历、私有仓链接}。

## 2. 核心要求

- 配置目录：{选择、拒绝路径、持久化与重开；命令、退出码、数字}。
- 临床试验：{建档/检索/匹配/收藏；候选池、全表/返回数、快照日、各通道终态及实际查过数量}。
- 患者与记录：{新建、SQLite、demo保护、隔离、刷新；证据}。
- 模块及 MinerU：{六部件逐项状态、本机/云端证据、未验证原因}。

## 3. 疾病概要与一图秀

- 本仓原型 URL、primer/page-view/M2 命令、退出码及断言数；各自 `--self-test` 注入结果与退出码。
- 曲线、单点、事件泳道、路径稳定、选择上限与节点回源的实测和基准对照；缺证据写未验证。

## 4. 原生 AI 面板

- `newSession` / `subscribe` / `ensureSession(...)` / `Boolean(conversation)` 计数与扫描范围；checker 及 self-test 结果。
- 安装副本、宿主实际创建/复用/取消/错误/草稿行为分别写实测或未验证。

## 5. 自动检查

逐项列七件门禁、各自 self-test、`npm test`、`npm run audit`、完整 `npm run check` 和打包：命令、退出码、通过/总数、失败与跳过。若检查器 self-test 以退出 0 表示成功抓到注入缺陷，写清被触发的失败数，不把它误写成产品失败。

## 6. D2/D3 与回流

独立审查 A–H 四态计数和 P0；D3 修复轮次、剩余问题、复跑证据与停修原因。M7/M8 草稿、发布和 PR 状态分开写；M9 starter 本地提交、测试、远端状态分开写。

## 7. 未验证与异常

患者/临床审核、真实 Desktop 点击、云 Token 与上游、通道 FAILED/DENIED/401、网络/权限/额度异常、版本不一致和依赖告警；标明证据时间与后果。失败通道不计为已查过，零候选不等于无研究。

## 8. 待决事项（最多三条）

列具体决定、影响和需要谁处理；无需决定写「无」。
